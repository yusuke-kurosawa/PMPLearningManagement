# GitHub Actions Workflow Creation Prompts 🚀

## 新規ワークフロー作成プロンプト

### 基本テンプレート
```
新しいGitHub Actionsワークフローを作成してください。

要件:
- 目的: {ワークフローの目的}
- トリガー: {実行タイミング}
- 処理内容: {実行する処理}
- 環境: {対象環境}
- 依存関係: {必要な外部サービスやツール}

制約事項:
- 実行時間: {目標時間}分以内
- セキュリティ: {特別な要件があれば}
- コスト: {リソース制限があれば}

期待される成果:
- {成果物1}
- {成果物2}
```

### カテゴリ別テンプレート

#### 📦 デプロイメントワークフロー
```
本番環境へのデプロイメントワークフローを作成してください。

デプロイ要件:
- 環境: {production/staging/development}
- トリガー: {main push/tag/manual}
- ビルドステップ: {ビルドコマンド}
- デプロイ先: {GitHub Pages/AWS/Vercel等}
- ロールバック: {必要/不要}

検証項目:
- [ ] ビルド成功確認
- [ ] テスト通過確認
- [ ] セキュリティスキャン
- [ ] パフォーマンステスト

通知設定:
- 成功時: {通知先}
- 失敗時: {通知先とエスカレーション}
```

#### 🧪 テストワークフロー
```
自動テストワークフローを作成してください。

テスト要件:
- テストタイプ: {unit/integration/e2e}
- 対象: {フロントエンド/バックエンド/全体}
- カバレッジ目標: {XX}%
- 並列実行: {必要/不要}

テスト環境:
- Node.js: {バージョン}
- ブラウザ: {対象ブラウザ}
- データベース: {必要な場合}

レポート:
- カバレッジレポート: {形式}
- テスト結果: {表示方法}
```

#### 🔒 セキュリティスキャン
```
セキュリティ監査ワークフローを作成してください。

スキャン要件:
- 対象: {コード/依存関係/コンテナ}
- ツール: {Snyk/CodeQL/Trivy等}
- 重要度: {critical/high/medium/low}
- 頻度: {daily/weekly/on-push}

アクション:
- 脆弱性検出時: {ブロック/警告/通知}
- 自動修正: {有効/無効}
- レポート生成: {形式と保存先}
```

## ワークフロー最適化プロンプト

### パフォーマンス改善
```
既存のワークフロー [{ワークフロー名}] を最適化してください。

現状の問題:
- 実行時間: 現在{X}分 → 目標{Y}分
- ボトルネック: {特定された遅い処理}
- リソース使用: {CPU/メモリの状況}

最適化の方向性:
- [ ] ジョブの並列化
- [ ] キャッシュの活用
- [ ] 不要な処理の削除
- [ ] 条件付き実行の追加

制約:
- 既存の機能を維持
- セキュリティレベルを下げない
- コストを増加させない
```

### セキュリティ強化
```
ワークフロー [{ワークフロー名}] のセキュリティを強化してください。

セキュリティ要件:
- 権限: 最小権限の原則を適用
- シークレット: 安全な管理方法
- 外部アクション: 信頼できるバージョン固定
- ログ: 機密情報のマスキング

チェック項目:
- [ ] permissions設定の見直し
- [ ] シークレットの使用箇所確認
- [ ] インジェクション対策
- [ ] 監査ログの実装
```

## ワークフローレビュープロンプト

### 品質レビュー
```
以下のワークフローをレビューしてください:
{ワークフローファイル内容}

レビュー観点:
1. 命名規則の遵守
2. コメントの適切性
3. エラーハンドリング
4. パフォーマンス
5. セキュリティ
6. 保守性

改善提案を含めて報告してください。
```

### 準拠性チェック
```
ワークフロー [{ファイル名}] がプロジェクト標準に準拠しているか確認してください。

チェック項目:
- [ ] WORKFLOW_STANDARDS.mdとの整合性
- [ ] 命名規則（ファイル名、ジョブ名、ステップ名）
- [ ] 必須要素の存在（ヘッダー、権限、タイムアウト）
- [ ] 日本語コメントの記載
- [ ] セキュリティベストプラクティス

非準拠箇所と修正方法を報告してください。
```

## 自動化拡張プロンプト

## 使用例

### 完全な新規作成リクエスト例
```
PMPLearningManagementプロジェクトに、日次のセキュリティスキャンワークフローを作成してください。

要件:
- 毎日午前2時（JST）に実行
- mainブランチと開発ブランチをスキャン
- 依存関係の脆弱性チェック
- コードの静的解析
- Dockerイメージのスキャン（もしあれば）

成功基準:
- Critical/High脆弱性が0件
- 実行時間15分以内
- 結果をSlackに通知

プロジェクトのWORKFLOW_STANDARDS.mdに準拠し、
03-security-daily-scan.ymlという名前で作成してください。
```

## プロンプトのカスタマイズ

### プロジェクト固有の要件追加
```yaml
custom_requirements:
  naming:
    - 必ず日本語名を含める
    - プロジェクトプレフィックスを付ける
  
  security:
    - 特定のセキュリティツールを使用
    - 社内ポリシーへの準拠
  
  performance:
    - SLA要件の遵守
    - コスト上限の設定
  
  documentation:
    - 変更履歴の記録
    - 影響範囲の文書化
```

---

*これらのプロンプトテンプレートを使用することで、一貫性のある高品質なGitHub Actionsワークフローの作成、最適化、トラブルシューティングが可能になります。*
