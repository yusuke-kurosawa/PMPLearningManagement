# 主要な技術的決定事項

## アーキテクチャ決定記録 (ADR)

### ADR-001: React採用

**日付**: 2024-10-01
**ステータス**: 承認済み
**決定**: フロントエンドフレームワークとしてReactを採用
**理由**:

- 大規模エコシステム
- 優れたパフォーマンス
- 豊富な人材プール
  **代替案**: Vue.js, Angular

### ADR-002: TypeScript導入

**日付**: 2024-11-15
**ステータス**: 実装中
**決定**: 段階的にTypeScriptへ移行
**理由**:

- 型安全性の向上
- 開発体験の改善
- バグの早期発見
  **影響**: 全コンポーネントの段階的書き換え

### ADR-003: tRPC採用

**日付**: 2024-12-01
**ステータス**: 承認済み
**決定**: API通信にtRPCを使用
**理由**:

- End-to-End型安全性
- 自動補完サポート
- RESTよりシンプル
  **代替案**: REST API, GraphQL

### ADR-004: GitHub Pages継続使用

**日付**: 2024-12-20
**ステータス**: 再検討中
**決定**: 当面GitHub Pagesを使用、将来AWS移行
**理由**:

- コスト削減
- 簡単なデプロイ
- 静的サイトに適している
  **移行計画**: 2025 Q2にAWS移行予定

### ADR-005: Prisma ORM採用

**日付**: 2025-01-05
**ステータス**: 承認済み
**決定**: データベースアクセスにPrismaを使用
**理由**:

- 型安全なクエリ
- マイグレーション管理
- 優れた開発体験
  **代替案**: TypeORM, Sequelize

## 設計原則

### 採用した設計原則

1. **Mobile-First Design**
   - モバイルから設計開始
   - プログレッシブエンハンスメント

2. **Component-Based Architecture**
   - 再利用可能なコンポーネント
   - 単一責任の原則

3. **Performance Budget**
   - 初期ロード < 3秒
   - バンドルサイズ < 500KB

4. **Security by Design**
   - ゼロトラストアーキテクチャ
   - 最小権限の原則

5. **Accessibility First**
   - WCAG 2.1 AA準拠
   - キーボードナビゲーション

## コーディング規約

### 決定した規約

- **命名規則**:
  - コンポーネント: PascalCase
  - 関数: camelCase
  - 定数: UPPER_SNAKE_CASE

- **ファイル構造**:
  - Feature-basedディレクトリ構造
  - Barrel exports使用

- **スタイルガイド**:
  - Prettier設定統一
  - ESLint規則適用

## データモデル決定

### ユーザーデータ

- 暗号化して保存
- PII最小化
- GDPR準拠

### 学習進捗データ

- リアルタイム同期
- オフライン対応
- バックアップ戦略

## セキュリティ決定

### 認証方式

- **決定**: JWT + Refresh Token
- **理由**: ステートレス、スケーラブル
- **実装**: AccessToken 15分、RefreshToken 7日

### 暗号化

- **決定**: AES-256-GCM
- **理由**: 強力かつ高速
- **適用範囲**: PII、パスワード、機密データ

### HTTPS

- **決定**: 全通信HTTPS必須
- **理由**: セキュリティ基本要件
- **実装**: HSTS有効化

## パフォーマンス決定

### キャッシュ戦略

- **L1**: ブラウザキャッシュ（静的資産）
- **L2**: Service Worker（オフライン対応）
- **L3**: CDN（エッジキャッシュ）
- **L4**: Redis（サーバーサイド）

### 最適化手法

- コード分割（ルートベース）
- 画像最適化（WebP、AVIF）
- Critical CSS インライン化
- Tree Shaking

## インフラストラクチャ決定

### 現在の構成

- **ホスティング**: GitHub Pages
- **CI/CD**: GitHub Actions
- **モニタリング**: 基本設定のみ

### 将来の構成（2025 Q2）

- **ホスティング**: AWS (ECS + ALB)
- **データベース**: RDS PostgreSQL
- **キャッシュ**: ElastiCache Redis
- **CDN**: CloudFront
- **モニタリング**: CloudWatch + Prometheus

## 非採用技術とその理由

### Redux

- **理由**: Context APIで十分
- **再検討条件**: 状態管理が複雑化した場合

### GraphQL

- **理由**: 現時点では過剰
- **再検討条件**: 複雑なデータ要求が増えた場合

### Kubernetes

- **理由**: ECSで十分
- **再検討条件**: マルチクラウド要件発生時

### MongoDB

- **理由**: PostgreSQLのJSONBで対応可能
- **再検討条件**: NoSQL特有の要件発生時
