# Claude Code Rules and Guidelines

## 基本原則

### 1. Issue-Driven Development (IDD) の徹底
- すべての変更は対応するIssueと関連付ける
- コミットメッセージには必ずIssue番号を含める
- PRタイトルまたは本文にIssue参照を含める

### 2. コード品質基準
- ESLint/Prettier設定に準拠
- TypeScriptの型安全性を維持
- 単体テストカバレッジ80%以上
- E2Eテストで主要フローをカバー

### 3. セキュリティ基準
- 認証・認可の適切な実装
- 入力値の検証とサニタイゼーション
- XSS/CSRF対策の実装
- セキュアな依存関係の使用

## コードレビュー基準

### 必須チェック項目
1. **IDD準拠**: Issue参照が含まれているか
2. **テスト**: 適切なテストが追加されているか
3. **ドキュメント**: 必要なドキュメント更新が含まれているか
4. **パフォーマンス**: パフォーマンスへの影響を考慮しているか
5. **セキュリティ**: セキュリティリスクがないか

### 推奨チェック項目
1. **可読性**: コードが理解しやすいか
2. **保守性**: 将来の変更が容易か
3. **再利用性**: コンポーネントの適切な分割
4. **一貫性**: プロジェクトの規約に従っているか
5. **最適化**: 不要な処理や重複がないか

## 自動化ルール

### PR自動処理
1. **自動ラベリング**: タイトル・本文からラベルを自動付与
2. **Issue自動リンク**: PR内のIssue番号を自動でリンク
3. **IDD準拠チェック**: Issue参照がない場合は警告
4. **CI/CDトリガー**: テスト・ビルド・デプロイの自動実行

### コード分析
1. **静的解析**: ESLint, TypeScript, Prettier
2. **セキュリティスキャン**: 依存関係の脆弱性チェック
3. **パフォーマンス分析**: バンドルサイズ、Lighthouse
4. **テストカバレッジ**: 単体テスト、E2Eテスト

## Claudeレビュー指示

### レビュー観点
1. **アーキテクチャ準拠**: 既存の設計パターンとの整合性
2. **ベストプラクティス**: React/TypeScriptのベストプラクティス
3. **アクセシビリティ**: WCAG 2.1 AA基準
4. **国際化**: 多言語対応の考慮
5. **エラーハンドリング**: 適切なエラー処理

### レビューコメントフォーマット
```markdown

### ✅ 良い点
- [具体的な良い実装]

### ⚠️ 改善提案
- [改善が必要な箇所と理由]
- [具体的な改善案]

### 💡 推奨事項
- [任意だが推奨される改善]

### 📊 スコア
- セキュリティ: X/5
- パフォーマンス: X/5
- 保守性: X/5
- テスト: X/5
```

## 禁止事項

### コード
- `console.log`の本番コードへの混入
- `any`型の過度な使用
- 未使用の変数・インポート
- ハードコードされた認証情報
- 同期的なファイル操作（ブラウザ環境）

### プロセス
- Issueなしでの直接的な変更
- テストなしでの機能追加
- レビューなしでのマージ
- 破壊的変更の事前通知なし

## 例外処理

### 緊急修正
- セキュリティ脆弱性の修正
- 本番環境の重大なバグ修正
- データ損失リスクの対処

これらの場合は事後的にIssueを作成し、適切なドキュメント化を行う。
