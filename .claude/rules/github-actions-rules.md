# GitHub Actions ルール定義

## 📋 必須ルール（MUST）

### 1. ワークフロー命名規則
- **形式**: `[カテゴリ]-[サブカテゴリ]-[アクション].yml`
- **カテゴリ**: ci, cd, security, quality, claudecode, idd
- **例**: `ci-basic-validation.yml`, `cd-production-deployment.yml`

### 2. ファイル構造
```yaml
# ================================================================
# Workflow: [ワークフロー名]
# Category: [カテゴリ] ([英語説明])
# Purpose: [目的の詳細説明]
# Trigger: [トリガー条件]
# Dependencies: [依存関係]
# Author: [作成者]
# Version: [バージョン]
# Last Modified: [最終更新日]
# ================================================================

name: [絵文字] [日本語名]

# ------------------------------------------------------------
# [セクション説明]
# ------------------------------------------------------------
```

### 3. 必須コメント要件
- **ヘッダーコメント**: 全ワークフローに必須
- **セクションコメント**: 各主要セクションに説明
- **日本語**: 全てのコメントは日本語で記載
- **目的説明**: なぜこの処理が必要かを明記

### 4. セキュリティ要件
- **permissions**: 最小権限の原則
- **timeout-minutes**: 全ジョブに必須設定
- **if条件**: 適切な実行条件の設定
- **secrets**: 環境変数での管理

### 5. パフォーマンス要件
- **キャッシュ**: Node.jsモジュールのキャッシュ必須
- **並列実行**: 可能な限り並列化
- **条件実行**: 不要な実行の回避
- **タイムアウト**: 適切な制限時間設定

## 🎯 推奨事項（SHOULD）

### 1. 再利用性
- Composite Actionsの活用
- 共通処理の抽象化
- パラメータ化された設計

### 2. 監視とログ
- 実行時間の記録
- エラーの詳細ログ
- 成功/失敗の通知

### 3. 品質保証
- テストカバレッジの確認
- コード品質チェック
- セキュリティスキャン

## ❌ 禁止事項（MUST NOT）

### 1. セキュリティ
- 平文でのシークレット記載
- 過度な権限設定
- 外部アクションのブランチ指定

### 2. 構造
- 重複した処理の実装
- ハードコードされた値
- エラーハンドリングの省略

### 3. パフォーマンス
- 無制限のタイムアウト
- 不要なステップの実行
- キャッシュの未使用

## 🚀 ClaudeCode Actions統合

### 必須統合項目
1. **自動コードレビュー**
   - PR作成時の自動分析
   - 改善提案の生成
   - セキュリティチェック

2. **Issue駆動開発**
   - Issue番号の必須参照
   - 自動ラベリング
   - 進捗追跡

3. **品質監視**
   - 品質メトリクス収集
   - アラート設定
   - レポート自動生成
