# DevOpsガイドライン

## 概要
PMPLearningManagementプロジェクトにおけるDevOps実践のための包括的ガイドライン。

## GitHub Actions命名規則

### ファイル名規則
```
{番号}-{カテゴリ}-{機能}.yml

番号: 01-99 (実行優先度)
カテゴリ:
  - idd: Issue-Driven Development
  - ci: 継続的インテグレーション
  - cd: 継続的デリバリー
  - test: テスト自動化
  - security: セキュリティ
  - perf: パフォーマンス
  - docs: ドキュメント
  - notify: 通知
```

### 実行優先度
- 01-09: コア機能（IDD、基本CI）
- 10-29: テスト・品質保証
- 30-49: セキュリティ・コンプライアンス
- 50-69: デプロイメント
- 70-89: 監視・分析
- 90-99: 補助機能

## ワークフロー設計原則

### 1. 単一責任の原則
各ワークフローは1つの明確な責任を持つ

### 2. 冪等性
同じ入力に対して常に同じ結果を返す

### 3. 失敗時の透明性
エラーメッセージは明確で実行可能な対処法を含む

### 4. 再利用性
共通処理は再利用可能なアクションとして定義

## 必須要素

### ワークフローヘッダー
```yaml
name: {番号} {カテゴリ} {機能名}
# 日本語での説明
# 関連Issue: #xxx

on:
  # トリガー定義

permissions:
  # 最小権限の原則

env:
  # 環境変数
```

### ジョブ構造
```yaml
jobs:
  job-name:
    name: 日本語名称
    runs-on: ubuntu-latest
    
    steps:
      - name: ステップの日本語説明
        # 処理内容
```

## エラーハンドリング

### 必須チェック
1. 前提条件の検証
2. エラー時の詳細ログ出力
3. リトライロジック（該当する場合）
4. 失敗通知

### エラーメッセージフォーマット
```
❌ エラー: {エラー内容}

詳細:
{詳細情報}

対処法:
1. {手順1}
2. {手順2}

関連ドキュメント: {リンク}
```

## セキュリティ

### シークレット管理
- ハードコードされた認証情報は禁止
- GitHub Secretsを使用
- 最小権限の原則を適用

### 権限設定
```yaml
permissions:
  contents: read      # 最小限の読み取り権限
  issues: write       # 必要な場合のみ書き込み権限
  pull-requests: write
```

## パフォーマンス最適化

### キャッシュ戦略
- 依存関係のキャッシュ
- ビルド成果物のキャッシュ
- テスト結果のキャッシュ

### 並列実行
- 独立したジョブは並列化
- マトリックス戦略の活用

## 監視とログ

### ログレベル
- DEBUG: 開発時のみ
- INFO: 通常の情報
- WARN: 警告
- ERROR: エラー

### メトリクス収集
- 実行時間
- 成功率
- リソース使用量

## ドキュメント要件

### 各ワークフローに必須
1. 目的と概要
2. トリガー条件
3. 前提条件
4. 出力と副作用
5. トラブルシューティング

### コメント規則
```yaml
# ========================================
# セクション名
# ========================================

# サブセクションの説明
# 複数行に渡る場合は
# このようにインデント

# TODO: 将来の改善点
# FIXME: 修正が必要な箇所
# NOTE: 重要な注意事項
```

## バージョニング

### ワークフローバージョン
- アクションは特定バージョンを指定
- 例: `actions/checkout@v4`

### 変更管理
- Breaking changeは事前通知
- 段階的な移行期間を設定

## テスト要件

### ワークフローテスト
1. ドライラン機能の実装
2. テスト環境での検証
3. 段階的ロールアウト

## チェックリスト

### 新規ワークフロー作成時
- [ ] 命名規則に準拠
- [ ] 日本語コメント100%
- [ ] エラーハンドリング実装
- [ ] 権限最小化
- [ ] ドキュメント作成
- [ ] テスト実施

### レビュー時
- [ ] セキュリティリスクなし
- [ ] パフォーマンス影響評価
- [ ] 既存ワークフローとの重複なし
- [ ] IDD準拠
