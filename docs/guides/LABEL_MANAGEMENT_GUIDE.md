# GitHub Issueラベル運用ガイド

## 概要

PMPラーニングマネジメントプロジェクトでは、効率的なIssue管理のため体系的なラベル分類システムを採用しています。このガイドでは、ラベルの適切な使用方法と運用ルールを説明します。

## ラベル体系の構成

### 🏷️ 6つの主要カテゴリ

| カテゴリ | プレフィックス | 目的 | 必須/任意 |
|----------|----------------|------|-----------|
| **種類** | `🔧 種類:` | Issueの性質を分類 | **必須** |
| **優先度** | `🔥 優先度:` | 対応の緊急性を示す | **必須** |
| **状況** | `🚀 状況:` | 作業の進捗状況を追跡 | 推奨 |
| **領域** | `⚛️ 領域:` | 担当コンポーネントを特定 | 推奨 |
| **ワークフロー** | `🚀 WF:` | CI/CD・自動化関連 | 任意 |
| **特別** | `🌟` | 特殊な分類・マーカー | 任意 |

## 📋 詳細ラベル一覧

### 🔧 種類 (必須)

| ラベル | 使用場面 | 例 |
|--------|----------|-----|
| `🐛 種類:バグ` | システムの不具合・異常動作 | ログイン失敗、画面崩れ、エラー発生 |
| `✨ 種類:新機能` | 全く新しい機能の追加 | 新しい学習モード、通知機能 |
| `🔧 種類:改善` | 既存機能の強化・使いやすさ向上 | UI改善、パフォーマンス向上 |
| `📚 種類:ドキュメント` | 文書の作成・更新 | README更新、API文書追加 |
| `🏗️ 種類:リファクタリング` | コード構造の改善 | コンポーネント整理、技術的負債解消 |
| `🔒 種類:セキュリティ` | セキュリティ関連の対応 | 脆弱性修正、認証強化 |
| `⚡ 種類:パフォーマンス` | 処理速度・効率の改善 | ローディング最適化、メモリ使用量削減 |
| `🧪 種類:テスト` | テストの追加・改善 | 単体テスト追加、E2Eテスト修正 |

### 🔥 優先度 (必須)

| ラベル | 対応目安 | 使用場面 |
|--------|----------|----------|
| `🚨 優先度:緊急` | 即座 | 本番停止、データ消失、セキュリティインシデント |
| `🔥 優先度:高` | 1-2日 | 主要機能の障害、ユーザー体験への重大影響 |
| `📋 優先度:中` | 1週間 | 通常の機能追加・改善（デフォルト） |
| `📌 優先度:低` | いつでも | 小さな改善、コードクリーンアップ |
| `💭 優先度:検討` | 未定 | 将来的な検討事項、アイデア段階 |

### 🚀 状況 (推奨)

| ラベル | 意味 | 担当者の行動 |
|--------|------|--------------|
| `🆕 状況:未着手` | まだ作業開始前 | アサイン待ち |
| `🔍 状況:調査中` | 問題の調査・分析中 | 原因調査、仕様確認中 |
| `🚀 状況:作業中` | 現在開発中 | コーディング・実装中 |
| `👀 状況:レビュー待ち` | コードレビュー・確認待ち | PR作成済み、レビュー依頼済み |
| `⏸️ 状況:保留` | 外部要因で一時停止 | 他の作業完了待ち、意思決定待ち |
| `✅ 状況:完了` | 作業完了、クローズ準備 | マージ済み、検証完了 |
| `❌ 状況:対応不要` | 対応しない | 重複、範囲外、無効 |

### ⚛️ 領域 (推奨)

| ラベル | 担当チーム/スキル | 含まれる要素 |
|--------|-------------------|---------------|
| `🎨 領域:UI/UX` | デザイナー、フロントエンド | デザイン、使いやすさ、アクセシビリティ |
| `⚛️ 領域:フロントエンド` | フロントエンド開発者 | React、TypeScript、状態管理 |
| `🔧 領域:バックエンド` | バックエンド開発者 | API、データベース、サーバーロジック |
| `📱 領域:モバイル` | モバイル開発者 | レスポンシブ、PWA、タッチ操作 |
| `🤖 領域:AI/ML` | AI/ML エンジニア | Claude統合、学習最適化、推薦システム |
| `📖 領域:学習機能` | 教育コンテンツ担当 | 学習コンテンツ、進捗管理、試験機能 |
| `📊 領域:視覚化` | データビジュアライゼーション | D3.js、グラフ、チャート |
| `🛠️ 領域:DevOps` | インフラ・DevOps | CI/CD、デプロイ、監視 |
| `🔐 領域:認証・認可` | セキュリティ担当 | ログイン、権限管理、セキュリティ |

### 🚀 ワークフロー (任意)

| ラベル | 対象領域 |
|--------|----------|
| `🚀 WF:CI/CD` | 継続的インテグレーション・デプロイメント |
| `🧪 WF:テスト自動化` | 自動テスト・品質保証 |
| `📦 WF:依存関係` | パッケージ更新・依存関係管理 |
| `📊 WF:監視・分析` | モニタリング・メトリクス |
| `🔍 WF:コードレビュー` | レビュープロセス改善 |
| `📋 WF:タスク管理` | プロジェクト管理・スプリント |

### 🌟 特別 (任意)

| ラベル | 用途 |
|--------|------|
| `🌟 初心者歓迎` | 新規参加者に適した課題 |
| `🆘 ヘルプ募集` | 外部支援が必要 |
| `💡 アイデア募集` | 解決方法のブレインストーミング |
| `⚠️ 破壊的変更` | 既存機能への影響あり |
| `🔄 重複` | 既存Issue/PRとの重複 |
| `❓ 質問` | 使い方・実装に関する質問 |

## 📖 運用ルール

### 必須ルール

1. **すべてのIssueに「種類」と「優先度」ラベルを必須付与**
2. **「状況」ラベルは作業進捗に応じてリアルタイム更新**
3. **Issue作成時は「🆕 状況:未着手」から開始**

### 推奨ルール

4. **「領域」ラベルで担当チーム・専門領域を明確化**
5. **CI/CD関連は「WF:」プレフィックスラベルを使用**
6. **複雑な課題は「💡 アイデア募集」で議論を促進**

### ラベルの組み合わせ例

#### 良い例 ✅

```
🐛 種類:バグ + 🔥 優先度:高 + 🚀 状況:作業中 + ⚛️ 領域:フロントエンド
→ フロントエンドの高優先度バグを現在修正中

✨ 種類:新機能 + 📋 優先度:中 + 🆕 状況:未着手 + 📖 領域:学習機能
→ 学習機能の新機能要求、未着手

🔧 種類:改善 + 📌 優先度:低 + 🌟 初心者歓迎 + 🎨 領域:UI/UX
→ 初心者向けのUI改善タスク
```

#### 悪い例 ❌

```
🐛 種類:バグ + ✨ 種類:新機能  ← 種類ラベルの重複
優先度ラベルなし               ← 必須ラベル不足
🚀 状況:作業中 + ✅ 状況:完了   ← 状況ラベルの矛盾
```

## 🛠️ 管理スクリプトの使用方法

### 基本コマンド

```bash
# 現在のラベル状況を確認
node .github/scripts/manage-labels.js status

# ラベル定義を検証
node .github/scripts/manage-labels.js validate

# 完全リセット（推奨）
node .github/scripts/manage-labels.js reset

# 個別操作
node .github/scripts/manage-labels.js backup      # バックアップ
node .github/scripts/manage-labels.js create      # 新規作成
node .github/scripts/manage-labels.js update      # 更新
node .github/scripts/manage-labels.js delete-old  # 旧ラベル削除
```

### 運用フロー

1. **初回設定**
   ```bash
   node .github/scripts/manage-labels.js reset
   ```

2. **定期メンテナンス**
   ```bash
   # 月1回程度実行
   node .github/scripts/manage-labels.js validate
   node .github/scripts/manage-labels.js update
   ```

3. **ラベル体系変更時**
   ```bash
   # labels-definition.json 編集後
   node .github/scripts/manage-labels.js validate
   node .github/scripts/manage-labels.js reset
   ```

## 📊 効果的な Issue 管理

### Issue作成時のチェックリスト

- [ ] 適切な「種類」ラベルを選択
- [ ] 「優先度」を適切に設定
- [ ] 「状況:未着手」を設定
- [ ] 関連する「領域」ラベルを追加
- [ ] 必要に応じて「特別」ラベルを追加

### Issue更新のタイミング

| タイミング | 更新するラベル | 例 |
|------------|----------------|-----|
| 作業開始時 | `状況:未着手` → `状況:作業中` | アサイン後、実装開始時 |
| 調査が必要 | `状況:未着手` → `状況:調査中` | 原因不明のバグ等 |
| PR作成時 | `状況:作業中` → `状況:レビュー待ち` | コードレビュー依頼時 |
| 外部待ち | `状況:作業中` → `状況:保留` | 他チームの作業待ち |
| 完了時 | `状況:レビュー待ち` → `状況:完了` | マージ・デプロイ完了時 |

### フィルタリング活用例

```
# 緊急対応が必要な課題
label:"🚨 優先度:緊急" is:open

# フロントエンド担当の未着手タスク
label:"⚛️ 領域:フロントエンド" label:"🆕 状況:未着手" is:open

# 初心者向けの課題
label:"🌟 初心者歓迎" is:open

# レビュー待ちの課題
label:"👀 状況:レビュー待ち" is:open

# CI/CD関連の課題
label:"🚀 WF:CI/CD" is:open
```

## 🔄 継続的改善

### 月次レビュー項目

1. **ラベル使用状況の分析**
   - 最も使用されているラベルの確認
   - 未使用ラベルの特定

2. **運用ルールの遵守状況**
   - 必須ラベル付与率の確認
   - 状況ラベル更新の遅延確認

3. **ラベル体系の改善検討**
   - 新しいカテゴリの必要性
   - ラベル名の分かりやすさ向上

### 改善提案の流れ

1. Issue作成（`💡 アイデア募集` ラベル付与）
2. チーム内での議論・合意
3. `labels-definition.json` の更新
4. スクリプトでのラベル体系更新
5. 運用ガイドの更新
