## 🚀 基本的な使い方

### Claude AI Assistantとは？

Claude AI Assistantは、GitHub Issues と Pull Requests で以下の自動化を提供します：

- 📋 **Issue自動分析**: バグ・機能要求の自動分類、優先度設定
- 🔍 **コードレビュー**: セキュリティ・パフォーマンス・品質の包括的分析
- 💡 **実装提案**: ベストプラクティスに基づく実装アドバイス
- 📊 **プロジェクト分析**: Epic分解、工数見積もり、リスク評価

### 自動機能（無操作で実行）

以下は自動的に実行されます：

1. **Issue作成時**:
   - タイプ分類（Bug, Feature, Epic等）
   - 優先度設定（Critical, High, Medium, Low）
   - 関連コンポーネントの特定
   - 品質スコアと改善提案

2. **PR作成時**:
   - コード品質チェック
   - セキュリティ脆弱性スキャン
   - アーキテクチャ準拠確認
   - パフォーマンス影響評価

### 手動実行（@claudeコマンド）

特定の分析が必要な場合は `@claude` コマンドを使用：

```markdown
@claude analyze
@claude review  
@claude security
```

## 🤖 AIコマンドリファレンス

### 基本コマンド

#### `@claude`
汎用AI支援。状況に応じて最適な分析を実行。

**使用例**:
```markdown
@claude

このバグの修正方法について相談したいです。
```

**応答例**:
- 問題の分析
- 修正アプローチの提案
- 関連するベストプラクティス
- テスト方法の推奨

#### `@claude review`
包括的なコードレビュー実行。

**使用例**:
```markdown
@claude review

今回のPRはパフォーマンスに影響しそうなので、詳細にレビューをお願いします。
```

**応答内容**:
- コード品質分析
- パフォーマンス影響評価
- セキュリティチェック
- ベストプラクティス適合性

#### `@claude analyze`
詳細分析（パフォーマンス、影響範囲等）。

**使用例**:
```markdown
@claude analyze

この機能追加が既存システムに与える影響を分析してください。
```

### 専門分析コマンド

#### `@claude security`
セキュリティ重点レビュー。

**対象**:
- XSS/CSRF脆弱性
- 認証・認可の確認
- データ暗号化の妥当性
- 依存関係の脆弱性

**使用タイミング**:
- 認証機能の変更時
- 外部API統合時
- ユーザーデータ処理の追加時

#### `@claude performance`
パフォーマンス影響分析。

**分析内容**:
- Bundle sizeの変化
- レンダリング性能
- メモリ使用量
- Core Web Vitals

**使用タイミング**:
- 新しいライブラリ追加時
- 大きなコンポーネント変更時
- データ取得ロジック変更時

#### `@claude architecture`
アーキテクチャ準拠チェック。

**確認項目**:
- CLAUDE.mdガイドライン準拠
- 既存パターンとの整合性
- 設計原則の遵守
- 将来拡張性の考慮

#### `@claude mobile`
モバイル対応レビュー。

**チェック内容**:
- レスポンシブデザイン
- タッチ操作の最適化
- PWA機能への影響
- パフォーマンス（特にモバイル）

#### `@claude test`
テスト戦略・カバレッジ分析。

**分析内容**:
- テストカバレッジの評価
- 不足しているテストケース
- テスト戦略の提案
- E2Eテストの必要性

### プロジェクト管理コマンド

#### `@claude breakdown`
Epic/大規模タスクの詳細分解。

**使用例**:
```markdown
@claude breakdown

このEpicを具体的なタスクに分解してください。チーム4名、3ヶ月での実装を想定。
```

**提供内容**:
- フェーズごとの作業分解
- 各タスクの工数見積もり
- 依存関係の整理
- リスクの特定

#### `@claude estimate`
工数・難易度見積もり。

**見積もり対象**:
- 開発工数（人日）
- 実装難易度（Easy/Medium/Hard/Complex）
- 必要スキルセット
- 外部依存の確認

#### `@claude dependencies`
依存関係分析。

**分析内容**:
- 技術的依存関係
- 他のIssue/PRとの関連
- 外部システムへの依存
- チーム間の依存関係

#### `@claude roadmap`
実装ロードマップ生成。

**生成内容**:
- 段階的実装計画
- マイルストーンの設定
- リスク軽減策
- 品質チェックポイント

### ケース1: 緊急バグの迅速対応

```markdown

- ログイン画面でメールアドレス入力後、「サーバーエラー」表示
- Chrome DevTools で 500 Internal Server Error
- サーバーログに JWT validation エラー

**緊急対応が必要な理由**:
PMP試験直前の学習者に影響、ビジネス影響大

**すでに確認済み**:
- サーバーは正常稼働
- データベース接続OK
```

**AI応答例**:
```markdown

1. JWT秘密鍵の変更・期限切れ
2. 認証ライブラリのアップデートによる非互換性
3. 環境変数の設定ミス

**即座の対応策**:
1. **緊急回避**: ゲストモードでの学習アクセス提供
2. **ログ詳細確認**: `/logs/auth.log` の直近エントリ
3. **設定確認**: `JWT_SECRET` 環境変数の確認

**修正アプローチ（優先順）**:
1. JWT設定の復旧（15分）
2. 認証ライブラリの互換性確認（30分）  
3. ロールバック準備（30分）

**影響軽減策**:
- ステータスページでの障害通知
- Slackでのユーザー告知

**検証手順**:
1. ローカル環境での再現確認
2. ステージング環境での修正テスト
3. 段階的な本番復旧
```
