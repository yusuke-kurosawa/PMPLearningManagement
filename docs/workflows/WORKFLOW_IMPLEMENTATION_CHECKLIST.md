# 📋 GitHub Actions ワークフロー実装チェックリスト

このチェックリストは、GitHub Actionsワークフローの作成、更新、レビュー時に使用する包括的なガイドです。

## 🆕 新規ワークフロー作成時のチェックリスト

### 📝 計画フェーズ
- [ ] **目的の明確化**: ワークフローの目的と期待される成果を文書化
- [ ] **依存関係の特定**: 他のワークフローやリソースとの依存関係を明確化
- [ ] **実行頻度の決定**: トリガー条件と実行頻度を決定
- [ ] **リソース見積もり**: 実行時間とコストを見積もり
- [ ] **カテゴリの選択**: 適切なカテゴリ（deploy, test, security等）を選択

### 🏗️ 実装フェーズ

#### ファイル構造
- [ ] **ファイル名規則**: `{優先度}-{カテゴリ}-{機能}.yml` の形式に従う
- [ ] **配置場所**: `.github/workflows/` ディレクトリに配置
- [ ] **テンプレート使用**: 該当するテンプレートから開始

#### ヘッダーとメタデータ
- [ ] **ヘッダーコメント**: 標準ヘッダーコメントを記載
  ```yaml
  # ====================================================================
  # ワークフロー: {名前}
  # バージョン: {x.y.z}
  # 最終更新: {YYYY-MM-DD}
  # ====================================================================
  ```
- [ ] **目的の記載**: 明確な目的説明を記載
- [ ] **トリガー条件**: 実行条件を明記
- [ ] **依存関係**: 必要な依存関係を記載
- [ ] **実行時間**: 予想実行時間を記載
- [ ] **コスト見積**: 推定コストを記載

#### ワークフロー名
- [ ] **絵文字の使用**: カテゴリに応じた適切な絵文字を使用
- [ ] **日英併記**: 日本語と英語の両方で記載
- [ ] **簡潔性**: 50文字以内で記載

#### トリガー設定
- [ ] **workflow_dispatch**: 手動実行トリガーを必ず含める
- [ ] **適切なトリガー**: 必要最小限のトリガーのみ設定
- [ ] **パス除外**: 不要なファイルの変更を除外
- [ ] **ブランチ制限**: 適切なブランチのみでトリガー

#### 権限設定
- [ ] **最小権限の原則**: 必要最小限の権限のみ付与
- [ ] **明示的な権限**: permissionsブロックで明示的に定義
- [ ] **権限の文書化**: なぜその権限が必要かコメントで説明

#### 環境変数
- [ ] **グローバル変数**: envブロックで共通変数を定義
- [ ] **命名規則**: UPPER_SNAKE_CASEを使用
- [ ] **デフォルト値**: 適切なデフォルト値を設定
- [ ] **シークレット管理**: シークレットは環境変数経由で使用

#### 並行実行制御
- [ ] **concurrencyグループ**: 適切なグループを設定
- [ ] **cancel-in-progress**: mainブランチ以外は true に設定
- [ ] **リソース競合**: リソース競合を避ける設計

#### ジョブ設計
- [ ] **ジョブ名**: 日英併記で明確な名前
- [ ] **タイムアウト**: timeout-minutesを必ず設定
- [ ] **ランナー選択**: 適切なランナーを選択（通常ubuntu-latest）
- [ ] **依存関係**: needsで適切な依存関係を設定
- [ ] **条件付き実行**: 必要に応じてif条件を設定

#### ステップ実装
- [ ] **ステップ名**: 各ステップに明確な名前
- [ ] **公式アクション**: 可能な限り公式アクションを使用
- [ ] **バージョン固定**: アクションのバージョンを固定
- [ ] **エラーハンドリング**: 適切なエラー処理
- [ ] **ログ出力**: 適切なログとグループ化

#### キャッシング
- [ ] **依存関係キャッシュ**: npm/yarn依存関係をキャッシュ
- [ ] **ビルドキャッシュ**: ビルド成果物を適切にキャッシュ
- [ ] **キャッシュキー**: 適切なキャッシュキー戦略
- [ ] **restore-keys**: フォールバック用のrestore-keysを設定

#### アーティファクト
- [ ] **必要な成果物**: 必要な成果物のみアップロード
- [ ] **保持期間**: 適切な retention-days を設定（通常3-7日）
- [ ] **命名規則**: 一意で識別しやすい名前
- [ ] **サイズ制限**: アップロードサイズを確認

### 🔒 セキュリティフェーズ
- [ ] **シークレット**: ハードコードされたシークレットがない
- [ ] **インジェクション対策**: ユーザー入力を安全に処理
- [ ] **サードパーティアクション**: 信頼できるアクションのみ使用
- [ ] **権限の最小化**: 必要最小限の権限のみ

### 📊 パフォーマンスフェーズ
- [ ] **並列化**: 可能な限りジョブを並列化
- [ ] **キャッシュ最適化**: キャッシュヒット率を最大化
- [ ] **不要な実行の回避**: paths-ignoreやif条件で最適化
- [ ] **タイムアウト設定**: 適切なタイムアウト値

### 📝 ドキュメントフェーズ
- [ ] **README更新**: 必要に応じてREADMEを更新
- [ ] **ルールブック確認**: ルールブックとの整合性確認
- [ ] **変更履歴**: CHANGELOGやコミットメッセージに記載

## 🔄 既存ワークフロー更新時のチェックリスト

### 事前準備
- [ ] **影響分析**: 変更の影響範囲を分析
- [ ] **バックアップ**: 現在の設定をバックアップ
- [ ] **テスト計画**: テスト方法を計画

### 変更実施
- [ ] **バージョン更新**: ヘッダーのバージョンを更新
- [ ] **変更履歴**: 変更内容をコメントに記載
- [ ] **後方互換性**: 既存の動作を壊さない
- [ ] **段階的ロールアウト**: 可能な限り段階的に変更

### テスト
- [ ] **ドライラン**: 可能ならドライランモードでテスト
- [ ] **featureブランチ**: featureブランチでテスト
- [ ] **手動実行**: workflow_dispatchで手動テスト
- [ ] **ログ確認**: 実行ログを詳細に確認

## 👀 レビュー時のチェックリスト

### コードレビュー
- [ ] **命名規則準拠**: ファイル名とワークフロー名が規則に準拠
- [ ] **コメント**: 適切なコメントが記載されている
- [ ] **ロジック**: ワークフローのロジックが正しい
- [ ] **エラー処理**: 適切なエラー処理がある

### セキュリティレビュー
- [ ] **権限**: 最小権限の原則に従っている
- [ ] **シークレット**: シークレットが適切に管理されている
- [ ] **アクション**: 信頼できるアクションのみ使用
- [ ] **入力検証**: ユーザー入力が適切に検証されている

### パフォーマンスレビュー
- [ ] **実行時間**: 予想実行時間が妥当
- [ ] **リソース使用**: リソース使用が効率的
- [ ] **キャッシュ**: キャッシュが適切に使用されている
- [ ] **並列化**: 可能な部分が並列化されている

### ドキュメントレビュー
- [ ] **説明**: 目的と動作が明確に説明されている
- [ ] **依存関係**: 依存関係が明記されている
- [ ] **メンテナンス**: メンテナンス方法が明確

## 📈 定期レビューチェックリスト（月次）

### メトリクス分析
- [ ] **実行時間**: 各ワークフローの実行時間を分析
- [ ] **成功率**: 成功率を確認し、低いものを改善
- [ ] **コスト**: GitHub Actions使用料を確認
- [ ] **使用頻度**: 使用されていないワークフローを特定

### 最適化
- [ ] **ボトルネック**: ボトルネックを特定し改善
- [ ] **重複削除**: 重複したワークフローを統合
- [ ] **キャッシュ**: キャッシュ戦略を見直し
- [ ] **並列化**: さらなる並列化の機会を探る

### 更新
- [ ] **アクション更新**: 使用アクションを最新版に更新
- [ ] **ベストプラクティス**: 新しいベストプラクティスを適用
- [ ] **セキュリティ**: セキュリティアップデートを適用
- [ ] **ドキュメント**: ドキュメントを最新化

### クリーンアップ
- [ ] **不要削除**: 使用されていないワークフローを削除
- [ ] **アーティファクト**: 古いアーティファクトを削除
- [ ] **ログ**: 古いログを確認し必要なら保存
- [ ] **シークレット**: 使用されていないシークレットを削除

## 🚨 トラブルシューティングチェックリスト

### ワークフローが失敗する場合
- [ ] **ログ確認**: エラーログを詳細に確認
- [ ] **権限確認**: 必要な権限が付与されているか
- [ ] **シークレット**: シークレットが正しく設定されているか
- [ ] **依存関係**: 依存関係が満たされているか
- [ ] **タイムアウト**: タイムアウトしていないか

### パフォーマンスが悪い場合
- [ ] **キャッシュ**: キャッシュが効いているか
- [ ] **並列化**: 並列実行できる部分があるか
- [ ] **ランナー**: より高性能なランナーが必要か
- [ ] **最適化**: 不要な処理がないか

### コストが高い場合
- [ ] **実行頻度**: 実行頻度を減らせるか
- [ ] **実行時間**: 実行時間を短縮できるか
- [ ] **アーティファクト**: 保持期間を短縮できるか
- [ ] **セルフホスト**: セルフホストランナーを検討
