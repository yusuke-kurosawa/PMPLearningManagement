# GitHub Actions ワークフロー一覧

## 📋 概要

このディレクトリには、PMPLearningManagementプロジェクトのCI/CDパイプラインを構成するGitHub Actionsワークフローが含まれています。すべてのワークフローは日本語チーム向けに標準化され、包括的なコメントと統一された命名規則に従っています。

## 🎯 標準化について

- **標準仕様書**: [`WORKFLOW_STANDARDS.md`](WORKFLOW_STANDARDS.md) - 包括的な標準仕様とガイドライン
- **テンプレート**: [`00-template-workflow.yml`](00-template-workflow.yml) - 新規ワークフロー作成用テンプレート  
- **実装サマリー**: [`IMPLEMENTATION_SUMMARY.md`](IMPLEMENTATION_SUMMARY.md) - 標準化の成果と結果

## 📦 デプロイメント関連

### deploy.yml - 📦 本番デプロイメント & PWA検証 ⭐ 標準化済み

- **目的**: アプリケーションをGitHub Pagesにデプロイし、PWA要件の検証とパフォーマンス監視を実行
- **実行**: mainブランチへのプッシュ時、プルリクエスト時
- **主な処理**: コード品質チェック、セキュリティ監査、ビルド、デプロイ、Lighthouse監査

## 🧪 テスト関連

### test.yml - 🧪 統合テストスイート実行 ⭐ 標準化済み

- **目的**: 単体テスト、統合テスト、E2Eテストを実行し、コードカバレッジの測定と品質保証を行う
- **実行**: push、PR、毎日午前2時（定期実行）
- **主な処理**: Vitest単体テスト、Playwright E2E、カバレッジレポート

### test-parallel.yml - 並列テスト実行（6人チーム）

- **目的**: 6人チーム体制での並列テスト実行により、テスト実行時間を短縮
- **実行**: main/developブランチへのプッシュ時、PR時
- **主な処理**: テストスイートの6分割、並列実行、結果集約

### advanced-testing.yml - 高度テストスイート

- **目的**: ミューテーションテスト、プロパティベーステスト、カオステストなどの高度なテストを実行
- **実行**: main/developブランチへのプッシュ時、週末の定期実行
- **主な処理**: Strykerミューテーションテスト、プロパティベーステスト、カオステスト

### integration-test.yml - 統合テストスイート（フェーズ5-6）

- **目的**: システム全体の統合テストを実行し、コンポーネント間の連携と動作を検証
- **実行**: mainブランチへのプッシュ時、PR時
- **主な処理**: API統合テスト、データベース統合テスト、E2Eテスト

## 🔍 品質管理

### pr-validation.yml - 🔍 プルリクエスト品質検証 ⭐ 標準化済み

- **目的**: プルリクエストの品質検証と自動レビューを実行し、マージ前に問題を早期発見
- **実行**: PRのオープン、更新、再オープン時
- **主な処理**: PR情報収集、ラベリング、コード品質チェック、セキュリティスキャン

### advanced-quality-gates.yml - 高度品質ゲート（6人チーム並列実行）

- **目的**: 6人チーム体制での並列品質チェックを実行し、90%+カバレッジを達成
- **実行**: main/developブランチへのプッシュ時、PR時
- **主な処理**: 各専門チームによる並列品質チェック（コード、セキュリティ、テスト、パフォーマンス、ドキュメント、デプロイ）

## 🔒 セキュリティ

### security-scan.yml - 🔒 セキュリティ脆弱性監査 ⭐ 標準化済み

- **目的**: コードベースのセキュリティ脆弱性を検出し、依存関係の脆弱性をスキャン
- **実行**: main/developブランチへのプッシュ時、毎日午前3時
- **主な処理**: 依存関係スキャン、CodeQL分析、シークレット検出、SARIF レポート生成

### zero-trust-security.yml - ゼロトラストセキュリティ実装

- **目的**: ゼロトラストセキュリティモデルと高度なセキュリティテストを実装
- **実行**: main/developブランチへのプッシュ時、毎日午前3時
- **主な処理**: アイデンティティ検証、最小権限適用、継続的セキュリティ監視

### infrastructure-security.yml - インフラストラクチャセキュリティ監査

- **目的**: インフラストラクチャのセキュリティを継続的に監査し、脆弱性を早期検出
- **実行**: 週次（水曜日午前2時）、手動実行
- **主な処理**: IaCスキャン、コンテナイメージ検査、ネットワークセキュリティ検証

## 📊 監視・パフォーマンス

### performance-monitoring.yml - 📊 パフォーマンス継続監視 ⭐ 標準化済み

- **目的**: モバイルファーストPWAアプリケーションのパフォーマンスを継続的に監視
- **実行**: main/developブランチへのプッシュ時、6時間ごと
- **主な処理**: バンドルサイズ分析、Lighthouse スコア測定、Core Web Vitals計測

### observability.yml - オブザーバビリティスタックデプロイ

- **目的**: Prometheus、Grafana、Lokiなどの監視スタックをデプロイし、可観測性を確保
- **実行**: mainブランチへのプッシュ時（監視設定変更時）
- **主な処理**: Prometheusデプロイ、Grafanaダッシュボード構築、ログ集約設定

### monitoring-setup.yml - 監視&オブザーバビリティセットアップ

- **目的**: アプリケーションの監視システムを構築し、リアルタイムでパフォーマンスと可用性を監視
- **実行**: mainブランチへのプッシュ時、監視設定ファイル変更時
- **主な処理**: 監視エージェントデプロイ、メトリクス収集設定、アラートルール設定

## 🤖 自動化・AI支援

### ai-assisted-review.yml - 🤖 AI支援コードレビュー ⭐ 標準化済み

- **目的**: AIを活用してコード品質を自動レビューし、変更に応じた最適なテストを選択・実行
- **実行**: main/developブランチへのPR時、mainブランチへのプッシュ時
- **主な処理**: AI品質分析、スマートテスト選択、パフォーマンス改善提案

### dependabot-auto-merge.yml - Dependabot自動マージ

- **目的**: Dependabotが作成した依存関係更新PRを自動的にレビュー、テスト、マージ
- **実行**: Dependabot PRのオープン時、レビュー承認時
- **主な処理**: セキュリティアップデート確認、テスト実行、自動マージ

## 🔧 開発支援

### developer-experience.yml - 開発者体験向上

- **目的**: 開発者の生産性を向上させるツールやプロセスを自動化し、開発体験を最適化
- **実行**: main/developブランチへのプッシュ時、PR時
- **主な処理**: 開発環境自動セットアップ、コード品質レポート生成、DXスコア計測

### test-data-management.yml - テストデータ管理&環境セットアップ

- **目的**: テストデータの管理とテスト環境の自動セットアップを行い、一貫性のあるテスト実行環境を提供
- **実行**: main/developブランチへのプッシュ時、毎日午前0時
- **主な処理**: テストデータベースセットアップ、モックデータ生成、テスト環境検証

## ⚖️ コンプライアンス・ガバナンス

### compliance-audit.yml - コンプライアンス監査&ガバナンス

- **目的**: SOC 2、GDPR等のコンプライアンス要件を自動チェックし、セキュリティとプライバシーのガバナンスを維持
- **実行**: mainブランチへのプッシュ時、毎日午前2時
- **主な処理**: SOC 2チェック、GDPR検証、セキュリティポリシー確認、コンプライアンスレポート生成

### feature-management.yml - 機能管理&価値提供

- **目的**: 機能フラグ管理とバリューストリーム管理を通じて、段階的なリリースと価値提供の測定を行う
- **実行**: main/developブランチへのプッシュ時、feature/\*ブランチへのプッシュ時
- **主な処理**: 機能フラグ構成管理、A/Bテスト、カナリアリリース、バリューストリームメトリクス収集

### dependency-health-check.yml - 依存関係ヘルスチェック

- **目的**: プロジェクトの依存関係を監視し、脆弱性や更新が必要なパッケージを検出
- **実行**: main/developブランチへのプッシュ時、毎週月曜日
- **主な処理**: 脆弱性スキャン、古いパッケージ検出、ライセンスコンプライアンス、更新推奨レポート

## 🔔 通知・レポート

### notifications.yml - 通知&監視

- **目的**: ビルド、テスト、デプロイの結果を監視し、チームに適切な通知を送信
- **実行**: ワークフロー完了時、PR イベント時
- **主な処理**: ワークフロー結果集約、Slack/Teams通知、ダッシュボード更新、アラート管理

## 使用方法

各ワークフローは、指定されたトリガーに基づいて自動的に実行されます。手動実行が必要な場合は、GitHubのActionsタブから`workflow_dispatch`対応のワークフローを選択して実行できます。

## カスタマイズ

ワークフローをカスタマイズする場合は、各YAMLファイルを編集してください。変更を加える前に、既存の設定とドキュメントを確認することをお勧めします。

## トラブルシューティング

ワークフローの実行に問題がある場合は、以下を確認してください：

1. GitHubのActionsタブでワークフローログを確認
2. 必要なシークレットが設定されているか確認
3. 権限設定（permissions）が適切か確認
4. 依存関係のバージョンが最新か確認
